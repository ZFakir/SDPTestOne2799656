Two cooperating sub-packages with a clear ingestion → query-time-metrics split:

- `analysis/` implements the one-pass ingest pipeline. `analyzeCommits.ts` streams `git log --no-merges -M50% --numstat` via `runGit` + `LogStreamParser`, buffers commits in batches of `BATCH_SIZE=500`, deduplicates authors through an in-process `identCache`, and writes `commits` / `commit_file_stats` rows inside a single `db.transaction`. `finalize.ts` materializes the directory tree into `repo_dirs` and calls `markReady` to flip the repo status.
- `metrics/` is read-only, composing SQL fragments around the fact table. `commitSet.ts` defines the shared `MetricFilters` interface (timestamp range, explicit SHA list, author id) plus the reusable `COMMIT_SOURCE_SQL` join chain (`commits → raw_idents → author_merges → canonical_authors/mailmap_map`) and helper SQL fragments (`AUTHOR_KEY_SQL`, `AUTHOR_NAME_SQL`, `AUTHOR_EMAIL_SQL`, `AUTHOR_KIND_SQL`). `objectMetrics.ts` adds path scoping (`PathScope = all | file | dir`) with index-friendly subtree predicates and provides `queryObjectSums`, `queryFileAggregates`, and `queryTimeseries`. `authorMetrics.ts` resolves raw idents to display authors (canonical > mailmap > raw precedence) and computes per-author churn and ownership fractions. `setMetrics.ts` composes these pieces into repository-wide DTOs.

Dependency direction: `metrics/*` depends on `commitSet` for filter SQL; `authorMetrics` additionally imports `pathScopeSql` from `objectMetrics`; `analysis` has no dependency on `metrics`. Both layers depend only on `../db/database` for prepared statements and on `../util/errors` for typed error helpers.
