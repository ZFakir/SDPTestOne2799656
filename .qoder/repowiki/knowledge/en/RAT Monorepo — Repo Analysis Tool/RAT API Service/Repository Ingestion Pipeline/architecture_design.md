The module is organized around a single orchestrator (`pipeline.ts`) that composes three source-handling helpers into a four-phase job: source acquisition (zip extraction via `zipSource.ts` or mirror clone via `cloneSource.ts`), validation (`validateRepo.ts`), commit analysis (delegated to `../analysis/analyzeCommits`), and finalization (`finalizeRepo`). `createPipeline` returns an `IngestPipeline` interface with `processZip` / `processClone`, both funneling through a shared `run` function that drives `jobStore` progress phases. `enqueueIngest` wires the pipeline onto a `JobQueue` for async execution. Dependency direction is one-way: this module depends on `../git`, `../analysis`, `../db`, `../jobs`, and `../util`; nothing inside the module imports back up to routes or controllers — they are consumed only through the exported interfaces.
