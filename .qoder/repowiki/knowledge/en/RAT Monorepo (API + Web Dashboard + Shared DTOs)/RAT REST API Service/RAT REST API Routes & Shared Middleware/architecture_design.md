Each file under `routes/` exports a factory function (e.g. `authorsRouter`, `metricsRouter`, `jobsRouter`) that takes a `Services` object and returns an Express `Router`; handlers are thin — they call `requireReadyRepository(services, req.params.repoId)` to resolve repository context, delegate domain logic to `../metrics/*` or `../db/canonicalStore`, and return typed DTOs from `@rat/shared`. The `middleware/` directory provides two cross-cutting concerns: `errorHandler.ts` centralizes error serialization — mapping `AppError`, `multer.MulterError`, body-parser-style errors, and unhandled exceptions into `{ code, message }` JSON responses — and `validate.ts` supplies Zod-based query/body parsers (`optionalString`, `optionalInt`, `optionalEnum`, `pagingParams`, `parseBody`) that throw structured `badRequest` errors. Dependency direction is one-way: routes depend on services/metrics/util; middleware has no dependency on routes.
