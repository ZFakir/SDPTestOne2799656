Three focused files form a thin layer over the `git` binary:
- `gitRunner.ts` is the process boundary: it exports `runGit(args, options)` which uses `node:child_process.spawn` to execute git with a hardened env (`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`, `LC_ALL=C`) and per-command `-C <dir> -c safe.directory=<dir>` flags. It supports optional streaming callbacks (`onStdoutLine`/`onStderrLine`) with an 8 KiB tail buffer and returns a `{code, stdout, stderr}` result even on non-zero exits; timeouts kill the child via SIGKILL.
- `identResolver.ts` builds on top of `baseGitArgs`/`runGit` to run `git check-mailmap --stdin` against HEAD's `.mailmap`, diffing raw idents from the DB against resolved ones and persisting changes in a single transaction into `mailmap_map`.
- `logParser.ts` implements a stateful `LogStreamParser` that consumes lines from `git log --numstat` formatted with `%x1e`/`%x1f` delimiters, handling C-quoted paths, rename syntax (`old => new`, brace form), and binary rows (skipped).
Dependency direction is one-way: `identResolver` depends on `gitRunner`; `logParser` has no dependency on the other two files. All public APIs are pure functions or a callback-based stream parser — no HTTP, no ORM coupling beyond the DB type import in `identResolver`.
