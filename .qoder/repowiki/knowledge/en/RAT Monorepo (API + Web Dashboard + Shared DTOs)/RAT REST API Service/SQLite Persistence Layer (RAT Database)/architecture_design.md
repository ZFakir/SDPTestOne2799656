Four-file leaf module with a strict downward dependency direction: consumers depend on this module; it depends only on `better-sqlite3` and Node's `fs`/`path`.
- `database.ts` is the sole entry point: `openDatabase(dbPath)` creates the `better-sqlite3` instance, enables WAL + NORMAL synchronous + foreign keys + busy timeout, then runs `schema.sql` via `db.exec`. It re-exports the `DB` type alias so stores never import `better-sqlite3` directly.
- `schema.sql` declares all tables (`repositories`, `jobs`, `raw_idents`, `commits`, `commit_file_stats`, `mailmap_map`, `canonical_authors`, `author_merges`, `repo_dirs`, plus `rollup_repo`/`rollup_file`/`rollup_day`) keyed by `repo_id` for multi-repository isolation, with `ON DELETE CASCADE` FKs and indexes on `(repo_id, ts)`, `(repo_id, raw_ident_id)`, `(repo_id, path)`, etc. Enumerated values are constrained at the SQL level via `CHECK (...) IN (...)`.
- `repoStore.ts` exposes a small CRUD surface over `repositories` (create/get/list/delete/status transitions).
- `canonicalStore.ts` implements the manual canonical-author tier over `canonical_authors` + `author_merges`, including validation helpers (`assertIdentsExist`, `assertIdentsFree`) and transactional create/update/delete operations using `db.transaction()`.
There is no ORM — every query is a hand-written parameterized statement built through `prepare(...).run()/get()/all()`, with row shapes expressed as local TypeScript interfaces cast via `as`.
