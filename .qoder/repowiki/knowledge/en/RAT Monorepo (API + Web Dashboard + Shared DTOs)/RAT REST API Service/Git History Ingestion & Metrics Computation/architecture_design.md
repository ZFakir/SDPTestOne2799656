Two cooperating sub-packages with a strict ingestion → query-time-metrics split and one-way dependency direction (analysis has no dependency on metrics; metrics imports only `ensureRollup` from `rollup.ts`).

- `analysis/` is the write path. `analyzeCommits.ts` streams `git log --no-merges -M50% --numstat` via `runGit` + `LogStreamParser`, buffers commits in batches of `BATCH_SIZE=500`, deduplicates authors through an in-process `identCache` keyed by `name\x00email`, and writes `commits` / `commit_file_stats` rows inside a single `db.transaction`. `finalize.ts` materializes ancestor directory paths into `repo_dirs`, calls `ensureRollup(db, repoId)` to build pre-computed aggregates, then flips the repo status via `markReady`.
- `metrics/` is read-only SQL composition layered on top of the fact tables. `commitSet.ts` defines the shared `MetricFilters` interface (timestamp range, explicit SHA list, author id) plus reusable SQL fragments (`COMMIT_SOURCE_SQL`, `AUTHOR_KEY_SQL`, `AUTHOR_NAME_SQL`, `AUTHOR_EMAIL_SQL`, `AUTHOR_KIND_SQL`) and the `buildFiltersSql` builder that always prepends `c.repo_id = ?`. `objectMetrics.ts` adds path scoping via a discriminated `PathScope` union (`all | file | dir`) with index-friendly subtree predicates (`path > d||'/' AND path < d||'0'`) and exposes `queryObjectSums`, `queryFileAggregates`, and `queryTimeseries` (day/week buckets via `strftime('%Y-W%W', ...)`). `authorMetrics.ts` resolves raw idents to display authors using the canonical > mailmap > raw precedence encoded in `KIND_RANK` and computes per-author churn and ownership fractions. `setMetrics.ts` composes these pieces into repository-wide DTOs and short-circuits unfiltered requests against the materialized rollup tables.
- `rollup.ts` provides the pre-computation tier: `rollup_repo`, `rollup_file`, `rollup_day` are built idempotently in one transaction and mirror the live `queryObjectSums`/`queryFileAggregates`/`queryTimeseries` SQL exactly so tests can assert parity between rollup and fact-table paths.

Both layers depend only on `../db/database` for prepared statements and `../util/errors` for typed error helpers.
