Three independent entry points with no shared code between them:
- `fix-native.js` — Node script that detects whether `better-sqlite3` loads, then downloads the matching prebuilt tarball from the `WiseLibs/better-sqlite3` GitHub release (based on `process.versions.modules`, platform, arch) and extracts it into `node_modules/better-sqlite3` via `tar`.
- `makeFixtureRepo.sh` — Bash script that creates a deterministic git repo under `storage/fixture-repo` (or an optional zip path), exercising every metric edge case: `.mailmap` author normalisation, rename-only / rename+edit, binary files, deletions, empty commits, merge commits (excluded from metrics), nested dirs, and branch merges; prints expected metric values for downstream comparison.
- `verifyMetrics.ts` — TypeScript oracle (run via `tsx`) that spawns `git log --no-merges -M50% --numstat`, parses the output with its own parser (deliberately not importing the API's parser), aggregates metrics locally, then diffs them against a running RAT API (`/api/repositories/{id}/metrics/*`). It discovers the stored repo by scanning `<RAT_STORAGE_DIR>/repos/<id>/repo.git` or a git tree under `<id>/src`.
Dependency direction is one-way: scripts depend on the surrounding repo layout (`storage/`, `node_modules/`) but nothing in the application imports these scripts.
